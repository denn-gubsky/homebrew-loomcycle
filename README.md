# homebrew-loomcycle

Homebrew tap for [loomcycle](https://github.com/denn-gubsky/loomcycle) — the agentic runtime, one Go binary owning the LLM tool-use loop.

## Install

```bash
brew tap denn-gubsky/loomcycle
brew install loomcycle
```

Or one-liner:

```bash
brew install denn-gubsky/loomcycle/loomcycle
```

## Supported platforms

The formula ships precompiled binaries for:

| OS | Arch |
|---|---|
| macOS | arm64 (Apple Silicon) |
| macOS | amd64 (Intel) |
| Linux | amd64 |
| Linux | arm64 |

Each binary is statically linked, embeds the React Web UI at `/ui`, and self-identifies via `loomcycle --version` (commit SHA, build timestamp, Go toolchain version).

## Configuration

`loomcycle` reads a YAML config file passed via `--config`. The convention is `~/.config/loomcycle/loomcycle.yaml`:

```bash
mkdir -p ~/.config/loomcycle
# Drop your loomcycle.yaml into the directory above.
# See https://github.com/denn-gubsky/loomcycle for documented examples.
loomcycle --config ~/.config/loomcycle/loomcycle.yaml
```

## Upgrade

```bash
brew update
brew upgrade loomcycle
```

The formula's `version` is bumped on every loomcycle release. Subscribe to [GitHub Releases](https://github.com/denn-gubsky/loomcycle/releases) for changelogs.

## Why a separate tap (vs. homebrew-core)

loomcycle is pre-1.0; homebrew-core's acceptance criteria (notable user base, stable releases, active maintenance over months) aren't a fit yet. Personal taps are the standard path for early-stage projects — same install ergonomics for users, no third-party gatekeeper.

When loomcycle matures to v1.0 with real production usage outside the original consumers, we may submit the formula to homebrew-core. Until then, this tap is the canonical Homebrew install path.

## Updating the formula (operator-only)

The formula is regenerated by goreleaser on every `v*` tag in the upstream loomcycle repository — operator action is just to tag a release. The release workflow:

1. Cross-compiles loomcycle for each supported `(OS, arch)` pair.
2. Packages each binary into a `loomcycle-<os>-<arch>.tar.gz` alongside `LICENSE` and `README.md`.
3. Uploads the tarballs + `SHA256SUMS` as GitHub release assets on the new tag.
4. Bumps `Formula/loomcycle.rb` in this repository with the new `version` + per-platform `sha256` values, then opens a PR (or commits directly, depending on the workflow's settings).

To hand-bump (if goreleaser is bypassed for some reason):

```bash
# Compute checksums against the GitHub release assets.
TAG=v0.8.X
for asset in loomcycle-darwin-arm64 loomcycle-darwin-amd64 loomcycle-linux-arm64 loomcycle-linux-amd64; do
  curl -sL "https://github.com/denn-gubsky/loomcycle/releases/download/$TAG/$asset.tar.gz" | sha256sum
done

# Update Formula/loomcycle.rb with the new version + sha256 values.
# Commit + push.
```

## Verifying the installed binary

```bash
loomcycle --version
# loomcycle version=v0.8.X commit=<sha> built=<rfc3339> go=goX.Y.Z

shasum -a 256 "$(which loomcycle)"
# Compare against the SHA256SUMS file on the GitHub release page.
```
